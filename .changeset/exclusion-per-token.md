Security: a rule's `notPaths` exclusion now removes the benign spellings it matches and re-tests the rule on what remains, instead of muting the rule for any whole subject that ends in an excluded spelling. `cat app/.env app/.env.example` ended in a template, so the exclusion matched the whole command line and the rule returned before the secret was ever considered — with the fix the exclusion cannot hide a secret that sits beside a template in the same command, in either order, including with `;` between them. Benign behaviour widened rather than narrowed: reading or catting templates alone still passes, a command naming only templates passes, and a template beside unrelated files (`cat app/.env.example README.md`) passes too — that last one was refused before, a tail test on the whole command line rather than a per-spelling exclusion. The bypass corpus pins all three directions (`dotenv-secret-beside-template` must block; `benign-dotenv-two-templates` and `benign-dotenv-template-beside-unrelated` must pass), the self-check fires the mixed command on every `herkos check`, and `validate`'s match/notMatch examples now evaluate exclusions the same way the hook does. Found while auditing the exclusion semantics against mixed commands.
